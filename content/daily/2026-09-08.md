**对工程/学习的即时含义：** 内部评测必须固定 harness 与裁判再比模型；采购/落地优先问「接了什么工具链、谁在跑环境」；安全与评测读者另记一条边栏——视觉通道注入与开源搜索 agent 数字均为**论文/作者自报**，勿当教程或可直接上线的 SLA。

## 主线 1：Harness 决定分数——架子、流程与评测基建同日收束

### 背景与触发

窗口内最响的一句口号来自 YC：**同一模型**，换一套 harness，ARC-AGI 分数可以从约 **30%** 拉到约 **95%**（**官方自报**，数字**待独立复现**）。人话版：考试分数越来越取决于「考场规则、草稿纸、监考怎么判」，而不只取决于考生脑子有多大。

**Harness**（这里指 agent 的**运行架子**：工具权限、记忆/checkpoint、重试与排队、提示与技能包、评测适配器）不是新词，但今天的材料第一次把「宣传数字 / 开源产品 / 评测基建」三条拧在同一根轴上：

1. **叙事层：** YC 公开帖把「架子 > 裸模」推到舆论中心（[X status](https://x.com/ycombinator/status/2096970626036855197)，**官方自报 · 待复现**）。  
2. **产品层：** DeepSeek 放出 [Harness `dsh-v0.1.3-alpha.2`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.3-alpha.2)——插件化 harness，带 Steer/排队、Web 打开、长会话（**FACT** Release）；LangChain [deepagents-talon `==0.0.7`](https://github.com/langchain-ai/deepagents/releases/tag/deepagents-talon%3D%3D0.0.7) 以**正式版**补 Discord + MCP + 历史 + checkpoint（**FACT**）。  
3. **评测层：** Harbor / Harbor-Index（[arXiv:2609.04298](https://arxiv.org/abs/2609.04298)）把 80+ agent 基准统一适配；精选难题集上最强配置也只约 **28%**（**论文自报**）。顾问名单含 Carlini 等——信号是「想当默认基建」，不是又一篇刷榜短文。

类比：把大模型当成发动机，harness 是变速箱、仪表盘和赛道规则。你换发动机当然能快；但同一台发动机换变速箱与轮胎，圈速也可以差一个数量级——YC 那组 30%→95% 就是在喊这件事。Harbor 的约 28% 则是另一记耳光：**统一赛道之后，头部配置仍远未「做完」难题集**。

### 机制 / 产品形态

把今日信号拆成可工程化的三层：

| 层 | 今日代表 | 它实际在管什么 |
|---|---|---|
| 运行架子 | DeepSeek Harness alpha | 插件边界、Steer/排队、浏览器打开、长会话——**谁能调方向、何时阻塞、上下文如何续** |
| 宿主与通道 | deepagents-talon 0.0.7 | Discord 入口 + MCP 工具面 + 历史/checkpoint——**会话可恢复、工具可插拔** |
| 评测适配 | Harbor / Harbor-Index | 多基准统一接口 + 精选难集——**同工具/同裁判下才谈「谁更强」** |

为何「架子」突然比「再发一个 orchestrator」更值钱？承上（09-07 主线）skills / 可移植技能包已经说明：Claude Code / Codex / Cursor 等把「能跑工具循环」商品化之后，边际收益转移到**可版本化的约束与流程**。今日材料是同叙事的下一帧——厂商用 alpha harness 明示插件化，框架商用正式版锁 Discord/MCP/checkpoint，学界用 Harbor 暗示：**没有统一适配，跨论文的 agent 分数几乎不可比**。

对 YC 数字的正确读法（避免两种极端）：

- **不要**写成「ARC-AGI 已被解决 / 模型一夜变强」——声明本身是 **同模换 harness**，且为 **官方自报、待复现**。  
- **也不要**写成「模型无所谓」——发动机仍设定能力上限；架子决定你能否逼近上限、以及分数是否可复现。

Harbor 的约 28% 与 YC 的约 95% **不在同一题集上**，禁止直接加减对比。有用的读法是对照：**宣传向「换架子暴涨」** 与 **基建向「统一难集仍很难」** 可以同时为真——前者提醒评测敏感于流程，后者提醒别把单一榜分数当成产品完备度。

### 对工程与产品的启示

1. **评测协议先于模型对比：** 内部 A/B 必须锁定工具集、重试预算、记忆是否开启、裁判模型——否则你在比 harness，却以为在比基座。  
2. **采购问卷加一列：** 「默认 harness / skill 包 / checkpoint 策略是什么？」比单问「用哪家模型」更接近真实体验差。  
3. **把 Harbor 类统一适配当长期债：** 自建 agent 评测集时，优先可插拔适配器，避免每个基准手写一套 glue。  
4. **宣传数字入库规则：** YC 类同模暴涨 → 标签 **官方自报/待复现**；对外材料禁止去掉「同模型」前提。  
5. **产品路线：** 若宿主已稳定，下季度 ROI 更可能来自插件化架子与可恢复会话，而不是再写一个从零 orchestrator。

## 主线 2：Google 气候应用落地——亚太加速器 + 国泰尾迹规避

### 背景与触发

同一窗口，Google / DeepMind 的高信号官博**不是新基座模型**，而是两条「把已有环境 AI 推进运营队列」的落地帖：

1. **FACT** [AI for the Planet Accelerator APAC](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/ai-planet-accelerator-apac/)（Sep 7）：亚太「AI 护地球」加速器首批 **16** 个团队，新加坡开营、约三个月，接到 AlphaEarth / SpeciesNet / Perch 等自家环境模型工具链。  
2. **FACT** [Contrail avoidance on ultra long-haul flights](https://blog.google/innovation-and-ai/models-and-research/google-research/contrail-avoidance-ultra-long-haul-flights/)（Sep 7）：与**国泰航空**试 AI 规避**冷凝尾迹**——预报进入签派与驾驶舱流程。

人话：**不是又发一个「更懂地球」的聊天模型，而是把实验室里的地球/物种/声学模型，塞进创业团队与航司运行手册。** 对只追 frontier 权重的读者，这两帖可以略读；对气候科技、航空运营、区域应用生态，这是窗口内最硬的「应用已进场」信号。

### 机制 / 产品形态

**冷凝尾迹（contrail）** 一句话：飞机在特定温湿度层留下的冰晶云带，可通过辐射效应产生显著气候影响；文称尾迹约占航空气候影响约 **1/3**（**官方叙述**，归因科学仍有文献争论，引用时保留来源）。规避的工程形态不是「让飞行员目测」，而是：

- 模型做可飞区域的尾迹生成预报；  
- 结果进入**签派（dispatch）**与驾驶舱可用的航路建议；  
- 用实际试飞与卫星等估算，回看「致暖影响」是否下降。

官方自报试飞规模与效果（**一律待核独立复现**）：目标 **>100** 班、**>80** 班跟随规避航路；估 **~40%** 尾迹致暖影响下降；港新走廊贡献试飞减排估量 **>50%**。读法要对齐航空运营现实——**改航有油耗/空域/时刻代价**，AI 建议必须嵌进既有签派约束，而不是单独的「绿色演示按钮」。

加速器侧机制更直白：DeepMind 不靠本窗新发基座，而是把 **AlphaEarth / SpeciesNet / Perch** 等已有能力当成「区域团队三个月能调用的工具箱」。类比：与其再开一家发动机厂，不如把现成发动机租给 16 支在地车队，看谁能跑完拉力赛。首期落点新加坡，窗口叙事强调 **APAC 队列**——对区域创业与科研合作是名额与工具链信号，对对齐研究者则是「应用线在动」。

### 对工程与产品的启示

1. **应用路线图模板：** 「模型能力已有 → 区域加速器/航司流程嵌入 → 官方自报效果 → 独立复现」分四栏跟踪，避免把博文当验收。  
2. **航空/物流读者：** 评估尾迹 AI 时同时问油耗惩罚、空域可用性、机组工作负荷——气候收益与运行成本是联合优化。  
3. **气候创业/科研：** APAC 16 强名单与工具链对接方式值得扫；重点不在蹭关键词，在能否调用 AlphaEarth 等具体 API/工作流。  
4. **内容写作纪律：** 一切百分比保留「官方自报/待核」；禁止二次放大成「航空减排已解决」。

## 主线 3：MaxKernel——多智能体接到 TPU 内核工程闭环

### 背景与触发

arXiv 周一宣布批里，大厂挂名最贴「agent × 系统」的一篇是 **MaxKernel**（[arXiv:2609.04523](https://arxiv.org/abs/2609.04523)，Google + DeepMind）。人话：不是让模型再写一个网页 CRUD，而是让**多智能体自动编写与调优 TPU kernel**，并与专家基线对照。

**TPU**（Tensor Processing Unit）是 Google 的定制加速器；**kernel** 在这里指跑在加速器上的底层算子实现（类似 GPU 上的 CUDA kernel）——慢一点，训练/推理账单就烫一点。把 coding agent 接到这一层，等于承认：**最贵的工程时间，有一部分可以交给「会查文档、会跑基准、会改代码」的 agent 环**。

这与主线 1 同属「架子与流程」家族，但对象不同：主线 1 谈的是通用 agent 产品与评测；MaxKernel 谈的是**加速器编译/算子**这一窄而深的闭环。类比：主线 1 是整车厂的总装流水线规范；MaxKernel 是引擎缸内燃烧室的加工机器人——观众更少，单件价值更高。

### 机制 / 产品形态

公开摘要级机制（细节以论文为准，下列为选题层复述，**非独立复现**）：

1. **多智能体分工：** 典型拆法是「提议实现 / 生成变体 / 跑微基准 / 根据画像再改」——用组织分工逼近专家迭代，而不是单次 prompt 出奇迹。  
2. **闭环在基准上：** 成败由可测延迟、吞吐或专家对照定义；没有基准就没有 MaxKernel 故事。  
3. **对标专家基线：** 叙事重点不是「完全取代编译器工程师」，而是 agent 能否在受控任务上逼近或辅助专家产物（**论文自报，待核**）。

与同批可对照的近邻（降为次要，防主线膨胀）：

- **Iris**（[arXiv:2609.04304](https://arxiv.org/abs/2609.04304)）：开源向搜索 agent（Iris-mini/pro），用网页超链反构多跳题 + SFT–RL climbing 冲 BrowseComp 等；作者自报管理开时 Iris-pro 达一组高分（摘要数字 **待核**）。强调同工具/同裁判，计划放权重与配方——和 Harbor「统一评」精神同向。  
- **Repeat-After-Me**（[arXiv:2609.04533](https://arxiv.org/abs/2609.04533)，FAIR Meta + Berkeley）：黑盒自适应**视觉**提示注入，逼前沿 **VLM**（Vision-Language Model，能看图的多模态模型）输出合规流程下本应拒绝的长有害内容，并演示 agent 部署路径。安全高相关；**本稿不展开攻击步骤**，只记风险形态：图像通道 + 真实 agent 工具链可能放大危害面。

今日为何抬 MaxKernel 做第三条主线：它给「agent 工程化」一个**可向硬件账单归因**的靶心——比泛化的「agent 更强了」更好写进系统团队季报。

### 证据与边界

| 声明 | 标签 | 来源 |
|---|---|---|
| MaxKernel 预印本存在；Google + DeepMind 挂名；任务为 TPU kernel 自动写/调 | **FACT**（元数据/标题层） | [arXiv:2609.04523](https://arxiv.org/abs/2609.04523) |
| 相对专家基线的具体升幅/胜率 | **论文自报** · **待核** | 以论文表格为准，本稿不臆造百分比 |
| Iris BrowseComp 等分数 | **作者自报** · **待核** | [arXiv:2609.04304](https://arxiv.org/abs/2609.04304) 摘要 |
| Repeat-After-Me 攻击有效性与 agent 路径 | **论文自报** · **待核**；勿当操作手册 | [arXiv:2609.04533](https://arxiv.org/abs/2609.04533) |

边界：预印本 ≠ 已合入生产编译栈；即便数字漂亮，也要问可维护性、安全审查（自动生成的 kernel 能否进信任路径）、以及是否只在基准子集上成立。系统团队引入类似环时，默认「人审 + 基准门禁」，不要端到端无人合并。

### 对工程与产品的启示

1. **系统/ML infra：** 盘点「专家反复手写、又有稳定微基准」的算子清单，才是 agent 闭环候选；没有基准先别上多智能体。  
2. **与主线 1 合并治理：** 通用 harness 的权限模型（能否跑基准、能否提交内核）要按最高风险路径设计——写 kernel 的 agent 权限 ≠ 写文档的 agent。  
3. **安全读者：** 把 Repeat-After-Me 记入 VLM/agent 红队议程：测文本拒绝不够，要测**图像通道 + 工具调用**组合；细节走内部红队，不公开复述利用步骤。  
4. **开源搜索 agent：** Iris 若放配方，优先复现其「同工具同裁判」协议，而不是只抄领袖榜数字。
